# Issue #16 — `preprocess_input()` 설계 제안

상태: 설계 승인됨 (2026-11-22). 이 문서는 요청된 진행 기록이며, 공식 AI-DLC 상태나 승인을 대신하지 않는다.

## 목표와 범위

`modules/features.py`의 `preprocess_input(img)`가 사용자 입력에 한해 종이 영역을 선택적으로 자르고, 화이트밸런스를 보정한 뒤 긴 변을 512px로 맞춘다. 함수 시그니처와 반환 형식은 유지하고 `contracts/interfaces.md`는 변경하지 않는다. 명화 경로에는 이 전처리를 적용하지 않는다.

## 제안

1. 기존 입력 정규화와 형식 검증(2D 그레이스케일 입력 및 RGBA 입력 처리 포함)을 유지한다.
2. RGB에서 밝고 채도가 낮은 종이 후보를 만들고, 형태학적 닫힘과 외곽 윤곽선으로 종이 영역을 찾는다. 충분히 크고 종이 경계로 판단할 수 있는 윤곽선이 있을 때만 그 윤곽선의 바운딩 박스를 자른다. 신뢰할 만한 종이 경계가 없으면 입력 전체를 유지한다.
3. 종이 경계가 검출된 컬러 입력에 한해, 잘린 이미지의 밝고 채도가 낮은 픽셀에서 채널별 중간값을 추정해 RGB 채널을 중립화한다. 채널별 보정량은 제한하고 결과를 uint8 범위로 클리핑한다. 신뢰할 수 있는 기준 픽셀이 없으면 보정을 건너뛴다. 그레이스케일 입력에는 색 틴트를 만들지 않도록 화이트밸런스를 적용하지 않는다.
4. 잘라내기와 보정 후 긴 변이 512px가 되도록 비율을 유지해 리사이즈한다. 축소는 `INTER_AREA`, 확대는 기존 동작과 같이 `INTER_CUBIC`을 사용한다.

## 대안과 판단

- **항상 이미지 테두리를 잘라내기:** 종이 경계가 없는 입력도 훼손할 수 있어 선택하지 않는다.
- **이미지 전체에 Gray-World 보정 적용:** 화면의 주요 색이 한쪽으로 치우친 작품의 색까지 바꿀 수 있어 선택하지 않는다. 종이 검출 시에만 종이 후보 픽셀을 기준으로 보정한다.
- **종이 미검출 시 오류 처리:** 임의 이미지 입력을 지원하는 앱의 기존 동작을 깨므로 선택하지 않는다. 미검출은 자르기·보정 생략으로 처리한다.

## 계약과 검증 계획

- 반환은 RGB `np.ndarray`, `uint8`, shape `(H, W, 3)`이며 긴 변은 512px이다. 원본 배열을 직접 수정하지 않는다.
- 대비되는 배경 안의 종이를 그린 합성 입력으로 종이 경계 자르기를 검증한다.
- 따뜻한 색조가 더해진 종이 입력에서 종이 픽셀의 중립성이 개선되고, 그레이스케일 입력은 색 틴트 없이 유지되는지 확인한다.
- 종이 경계가 없는 입력에서 예외 없이 전체 입력이 유지되는지 확인한다.
- 기존 스모크 테스트의 RGB/RGBA/그레이스케일 입력 및 계약 검사를 그대로 통과시킨다.
