## 다른 역할과 맞춘 결정

- **`direction`은 방향 일관성(0~1)이다** (PR #44 리뷰, C·D 합의안 A). 레이더는 변환 없이 그리고 라벨은 "선 방향 일관성"이다(PR #46). `compare()`의 z값 식은 그대로 쓴다. 각도의 원형 거리 문제는 정의를 바꿔 해결했다.
- 수치 특징 10개는 모두 0~1이라 `_radar_value()`는 범위만 자른다. C가 범위나 의미를 바꾸면 D에게 먼저 알리기로 했다.

- **CLIP 모델은 A가 #5에서 상수 하나로 정하고, `embed_text()`는 받은 문장을 그대로 임베딩한다** (PR #56 리뷰, 이슈 #5 댓글, 2026-11-26). `detect_type()`은 A의 함수를 통해 같은 모델을 쓴다. 틀(`"a photo of {}"`)은 `clip_keywords()` 쪽에서만 붙인다. 이 내용을 계약 표에 넣으려면 팀 합의 후 별도 PR로 한다(`AGENTS.md` 규칙 2).
- **분할은 다시 하지 않고, 중복을 감안해 평가한다** (D 결정, 2026-11-27, 이슈 #3 댓글). 처음에는 A에게 분할 전 묶기를 요청했지만(이슈 #3), PR #58은 이를 반영하지 않고 머지돼 #3이 닫혔다. #3은 다시 열지 않는다.
  - 이유: 검증셋 1,035장 중 26장(2.5%)만 학습셋 작품과 코사인 0.95 이상이고(0.99 이상 1장), #9 kNN에서 26장을 빼도 Top-1이 0.706 → 0.700(참고값, PR #59 리뷰)이었다. 다시 분할하면 `meta.csv`의 split이 바뀌어 진행 중인 #8·#9·#13과 C의 작품 기록을 다시 해야 한다.
  - 중복 목록: A가 학습셋과 코사인 0.95 이상인 검증셋 작품 id 목록을 A의 스크립트로 만들어 `artifacts/`에 둔다(파일 이름은 A가 정한다. 예: `near_duplicates.csv`, 열 `id`, `split`, `train_id`, `sim`). 계약 함수는 바꾸지 않는다. 0.95는 `similar_works()`의 `NEAR_DUPLICATE`와 같은 값이다.
  - 검증셋으로 낸 수치(#9~#15의 정확도·ECE, #27)는 "중복 포함"과 "중복 제외"를 둘 다 적는다.
  - #24 등급 경계는 중복을 뺀 검증셋으로 정한다. 중복은 `max_sim`이 0.95 이상으로 튀어 경계를 끌어올린다.
  - 테스트셋 중복 목록은 #26 최종 평가 때 같은 기준으로 처음 만들고, 제외 수치를 같이 낸다. 그 전에는 테스트셋을 열지 않는다(규칙 6).
  - 처음 확인할 때 테스트셋 임베딩도 학습셋과 비교했다(정답·정확도는 보지 않음). 규칙 6에 걸리지 않도록 테스트셋 수치는 PR·이슈에 적지 않았다. 앞으로 #26 전까지 중복 확인은 학습·검증셋만으로 한다.

## 정해야 할 것 (D)


- **#24 등급 경계를 정할 때 테스트셋 접근.** `similar_works()`는 색인 전체(train·val·test)를 검색한다(B 요청, PR #57). 앱에서는 괜찮지만, 검증셋으로 등급 경계를 정할 때 `max_sim`에 테스트셋 임베딩이 섞인다. 정답(라벨)을 쓰는 건 아니지만 규칙 6을 엄격히 지키려면 평가 코드에서는 학습셋만 검색하도록 막는다.
- **`NEAR_DUPLICATE`(0.95)가 충분한지.** 합성 참고 실험(PR #57 리뷰)에서 화면을 찍은 사본은 0.93~0.95라 자기 자신이 1위로 나왔고, 이 값은 `max_sim`으로 등급에도 들어간다. #13에서 B가 실제 색인으로 확인한 결과를 보고 계약 변경 여부를 정한다.

## #25 통합 때 볼 것

- `is_grayscale()`(C, 픽셀)과 `detect_type()`(B, CLIP)이 엇갈리는 경우의 처리. 예: 거의 한 색인 연한 그림이 흑백으로 판정되면 특징은 선만 쓰는데, 문장은 "이 그림은…"으로 시작한다. PR #42 3차 리뷰에서, 이 경우는 "색 조명 아래 스케치"와 픽셀이 같아 전처리로는 구별할 수 없다고 정리했다. 여기서 정해야 한다(예: `detect_type()`이 그림이라고 하면 색 특징도 쓴다).
- PR #42 제안대로 바뀌면 스케치는 전처리 후 흑백 3채널이 된다. 화면에 전처리된 이미지를 보여 준다면 사용자에게도 흑백으로 보인다.
