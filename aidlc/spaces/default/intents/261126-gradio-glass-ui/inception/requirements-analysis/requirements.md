# 요구사항 — #37 G안 Gradio 화면

## 의도 분석

- **목표**: 캔버스 시안 G(몰입형 글래스 바텀 시트)를 실제 Gradio 앱 화면으로 옮긴다. 휴대폰(Galaxy S24, 360×780) 기준으로, 카메라형 첫 화면에서 사진을 넣으면 분석 과정이 보이고, 결과·색·선·화풍을 한 장씩 넘겨 본다.
- **유형**: 기존 기능의 화면 개편(enhancement). 분석 파이프라인(`app.analyze()`)과 계약은 그대로 두고 화면 층만 바꾼다.
- **범위**: D 담당 파일(`app.py`, `modules/explain.py`)과 새 UI 파일(`static/g.css`, `static/g.js`). 출처: 요청 [desc], 질문 답 [Q1–Q4].
- **범위 추가 (2026-11-27)**: 처음에 범위 밖으로 뺐던 "1위 화가의 가장 닮은 명화 비교"와 "기록"을 사람의 요청으로 #37에 넣는다. 기록은 이 브라우저 안에만 저장하고, 명화 이미지는 파일이 있을 때만 보여 준다. 출처: 범위 추가 요청과 답 [Q5–Q10].

## 기능 요구사항

### FR1 첫 화면

- **FR1.1** 왼쪽 위에 렌즈 팔레트 아이콘만 둔다(글자·배경 없음, 40px, 누르는 영역 48px). 누르면 첫 화면 처음 상태로 돌아간다.
- **FR1.2** 위쪽 가운데에 안내 띠 "그림을 틀에 맞춰 주세요"를 둔다.
- **FR1.3** 화면 가운데에 4:5 촬영 틀(둥근 흰 꺾쇠 4개)을 두고, 틀 바깥은 반투명하게 어둡게 한다. 스캔 빛줄은 없다.
- **FR1.4** 배경은 실시간 카메라 미리보기를 쓸 수 있으면 그것을, 쓸 수 없으면(보안 주소가 아님·권한 거부·카메라 없음) 어두운 기본 배경을 보여 준다 [Q2].
- **FR1.5** 가운데 셔터: 실시간 카메라가 켜져 있으면 지금 화면을 찍어 분석을 시작하고, 아니면 기기의 이미지 선택 창을 연다 [Q2].
- **FR1.6** 왼쪽 아래 앨범 버튼(아이콘, 글자 없음)은 기기의 이미지 선택 창을 연다. 고른 이미지로 바로 분석을 시작한다.
- **FR1.7** 오른쪽 아래에 기록 버튼(아이콘만, 누르는 영역 48px)을 두고, 누르면 기록 화면(FR9)으로 간다. 도움말 버튼은 두지 않는다. (2026-11-27 범위 추가로 [Q3]의 "숨김"을 바꿈)
- **FR1.8** 첫 화면이 나타날 때 틀 바깥 어둡게 → 틀 → 안내 띠 → 아래 도크 → 셔터 순으로 약 0.8초 동안 차례로 나타난다.
- **FR1.9** 맨 아래에 `explain.DISCLAIMER`와 같은 뜻의 안내문을 항상 보인다.

### FR2 분석 중 화면

- **FR2.1** 고른(찍은) 이미지를 배경에 깔고, 흰 시트에 4단계(이미지 맞추기 → 소재·분위기 보기 → 색·선 재기 → 두 관점 합치기)를 완료·진행 중·대기로 보여 준다.
- **FR2.2** 단계 표시는 실제 분석 진행에 맞춰 바뀐다(분석 함수가 단계마다 화면을 갱신한다).
- **FR2.3** 분석이 끝나면 버튼 없이 결과 페이지로 넘어간다.
- **FR2.4** 왼쪽 위 아이콘을 누르거나 시트를 끌어내리면 확인 없이 분석을 멈추고 첫 화면으로 돌아간다.
- **FR2.5** 이미지 없이 분석이 호출되거나 분석 중 오류가 나면, 무엇이 잘못됐는지 한 줄로 알리고 첫 화면으로 돌아간다.

### FR3 결과 페이지 (1/3)

- **FR3.1** "사진을 그림처럼 놓고 보면"처럼 `TYPE_INTRO`에 따른 머리말, 1위 화가 이름(한글 이름이 있으면 한글, 아래에 원래 이름과 대표 화풍)을 보여 준다.
- **FR3.2** 1위 확률 %가 0에서 실제 값까지 약 0.9초 동안 빠르게 올라간다. 아래에 "%는 소재·분위기(CLIP)와 색·선(OpenCV)을 합친 확률이에요."를 보인다.
- **FR3.3** 신뢰 등급 칩(높음·보통·낮음, 막대 3칸 중 채운 칸 수와 글자로 구분)과 `LEVEL_NOTE`에 맞는 한 줄 설명을 보여 준다.
- **FR3.4** 등급이 높음·보통이면 `fuse()` Top 3를 카드 3개로 보여 준다(1위 강조).
- **FR3.5** CLIP 1위와 OpenCV 1위가 다르면 "분위기 · CLIP / 색감·선 · OpenCV" 두 칸으로 각각의 1위를 보여 주고, 같으면 "두 관점 모두 ○○를 1위로 봤어요"를 보여 준다.
- **FR3.6** 등급이 낮음이면 Top 3 대신 CLIP·OpenCV 상위 3개를 두 칸으로 따로 보여 주고, 다시 찍기 팁을 보여 준다.
- **FR3.7** 아래 버튼: "다시 찍기"(첫 화면), "가장 닮은 명화 보기"(명화 페이지, 등급이 낮음이면 "비슷한 명화 보기") [Q7].

### FR4 색·선 페이지 (2/3)

- **FR4.1** 내 이미지 특징과 1위 화가 평균을 겹친 레이더(다각형) 그래프를 SVG로 그린다. 축 이름은 `FEATURE_KO`를 따른다 [Q4].
- **FR4.2** 스케치(흑백 판정)이면 색 특징을 빼고 선 특징 5개로만 그린다.
- **FR4.3** 들어올 때 1위 평균 다각형이 펼쳐지고 → 내 이미지 다각형이 선을 따라 그려지고 → `why_top1` 축 글자는 파랑·굵게, `toward_top2` 축 글자는 주황·굵게 바뀐 뒤 → 아래 정보가 나타난다.
- **FR4.4** 아래 카드 2개: "○○ 평균에 가까운 특징"(`why_top1`), "○○ 쪽에 가까운 특징"(`toward_top2`, 2위 화가 이름). 비어 있으면 "해당 없음"으로 보인다.
- **FR4.5** 아래 버튼: "이전"(명화 페이지), "화풍 보기".
- **FR4.6** 명화 페이지에서 고른 명화의 특징(FR8.5)이 있으면 레이더 위에 탭 2개 "○○ 평균"·"이 명화"를 둔다. "이 명화"를 고르면 비교 다각형이 그 명화 값으로 바뀌고, 내 값과 차이가 가장 작은 축 2개를 파랑, 가장 큰 축 2개를 주황으로 표시하며 아래 카드 제목도 "이 명화와 비슷한 특징"·"이 명화와 다른 특징"으로 바뀐다. 특징이 없으면 탭을 숨긴다 [Q6].
- **FR4.7** 탭을 처음 눌렀을 때는 FR4.3처럼 그래프를 그린 뒤 차례로 나타나고, 그 뒤로 같은 탭을 다시 누르면 애니메이션 없이 바로 보여 준다.

### FR5 화풍 페이지 (3/3)

- **FR5.1** `styles_top3` 3개를 이름·%·막대로 보여 주고, 들어올 때 막대가 0에서 값까지 차오른다.
- **FR5.2** `keywords`를 칩으로 보여 준다.
- **FR5.3** 지표 4개(1·2위 차이, 엔트로피, 관점 차이 JSD, 데이터셋 유사도)를 값과 한 줄 뜻으로 보여 준다.
- **FR5.4** 안내문(DISCLAIMER 뜻)과 "명화 데이터는 WikiArt(비상업 연구용)" 출처를 보인다.
- **FR5.5** 아래 버튼: "처음으로"(결과 페이지), "다른 이미지로 해 보기"(첫 화면).

### FR6 화면 전환

- **FR6.1** 분석 중·결과·색·선·화풍은 흰 시트 하나가 페이지마다 정해진 높이로 부드럽게 움직이며 바뀐다. 시트 안 내용은 앞으로 갈 때 오른쪽에서, 뒤로 갈 때 왼쪽에서 들어온다.
- **FR6.2** 각 페이지의 내용은 위에서부터 차례로(약 0.08초 간격) 나타난다.
- **FR6.3** 위쪽 진행 막대는 결과·명화·색·선·화풍 4단계이고, 단계 이름을 누르면 그 페이지로 간다 [Q3][Q7].
- **FR6.4** 시트 위 손잡이를 아래로 120px 넘게 끌어 놓으면 시트가 내려가며 첫 화면이 나타난다. 덜 끌면 제자리로 돌아간다.
- **FR6.5** "다시 찍기"·"다른 이미지로 해 보기"·분석 중 아이콘도 FR6.4와 같은 내려가는 전환으로 첫 화면을 보여 준다.
- **FR6.6** 첫 화면으로 돌아온 뒤 셔터·앨범을 다시 누르면 새 분석이 처음부터 시작된다.

### FR7 화면용 데이터 (`explain.py`, 계약 밖 보조 함수)

- **FR7.1** `result` dict 하나로 화면에 필요한 값(이름·%·등급 문구·Top 3·두 관점·레이더 좌표·강조 축·화풍·키워드·지표)을 담은 JSON 직렬화 가능한 dict를 만드는 함수를 둔다.
- **FR7.2** 화가 한글 이름표를 두고, 표에 없는 이름은 원래 이름을 그대로 쓴다.
- **FR7.3** 레이더 좌표는 `_radar_value()`와 같은 값 범위 규칙을 쓴다(값은 0~1로 자름).
- **FR7.4** 명화 비교용 값(FR8)을 화면용 dict에 넣는다: 비교 명화 3점마다 화가 전체·짧은 이름, 작품 번호, 화풍 한글 이름, 유사도 %, 이미지 주소(없으면 비움), 대표색 5개와 레이더 값(특징이 없으면 비움), 그리고 내 대표색 5개. 이 값은 `result`와 `app.py`가 따로 넘기는 명화 목록으로만 만든다.

### FR8 명화 페이지 (결과와 색·선 사이)

- **FR8.1** 비교 명화 3점을 정한다: 등급이 높음·보통이면 1위 화가 작품 중 가장 닮은 1점을 먼저 두고, 나머지 2점은 화가와 상관없이 비슷한 순으로 채운다(같은 작품은 한 번만). 후보에 1위 화가 작품이 없거나 등급이 낮음이면 화가와 상관없이 비슷한 순 3점이다. 후보는 `classify.similar_works()`를 k를 크게(30) 한 번 더 불러 얻는다(함수는 고치지 않음) [Q5][Q7].
- **FR8.2** 시트 위에 머리말("1위 화가 ○○의 작품 중에서", 1위 화가 작품이 아니면 "화가와 상관없이 고른"), 제목("가장 닮은 명화예요", 낮음이거나 1위 화가 작품이 아니면 "가장 비슷한 명화예요")을 보이고, 내 사진과 고른 명화를 나란히 둔다. 각 그림 아래에 "내 사진"·종류, 명화 이름(화가 짧은 이름 #작품 번호)·화풍을 적는다.
- **FR8.3** 명화 이미지 파일이 없으면 그 자리에 화가 짧은 이름을 넣은 빈 카드를 보여 준다(깨진 이미지 표시 없음).
- **FR8.4** 시트에 "CLIP 유사도"를 %로 보여 준다. 들어올 때 막대가 차오르며 숫자가 0에서 실제 값까지 약 0.9초 동안 올라가고, 다 오르면 두 그림 사이에 유사도 배지가 나타난다. 아래에 "100%에 가까울수록 소재·분위기가 비슷해요."를 보인다.
- **FR8.5** "대표색 비교": 내 사진의 대표색 5개와 명화의 대표색 5개를 두 줄로 보여 준다. 명화 특징은 명화 이미지를 긴 변 512px로 줄인 뒤 `features.extract_features()`로 구하고 화이트밸런스는 하지 않는다. 명화 파일이 없으면 이 칸을 숨긴다 [Q6].
- **FR8.6** "다른 명화와 비교": 3점을 작은 그림(파일이 없으면 FR8.3 카드)과 "짧은 이름 · %"로 보여 준다. 누르면 고른 명화가 바뀌어 FR8.2·FR8.4·FR8.5가 그 명화로 다시 그려지고 FR8.4 움직임이 다시 돈다.
- **FR8.7** 아래 버튼: "이전"(결과 페이지), "색·선 비교 보기".
- **FR8.8** 명화 이미지는 `similar_works()`의 `path`가 저장소 안 `data/` 폴더의 실제 이미지 파일일 때만 브라우저에 보낸다. 그 밖의 경로는 이미지 없이 처리한다.
- **FR8.9** 비슷한 명화 후보가 하나도 없으면 명화 페이지와 진행 막대의 "명화"를 숨기고 결과 → 색·선으로 바로 간다.

### FR9 기록

- **FR9.1** 분석이 결과 페이지까지 끝나면 기록 1건을 자동으로 저장한다: 시각, 종류(사진·그림·스케치), 화가 이름(낮음이면 "닮은 화가 없음"), 1위 %, 신뢰 등급, 썸네일(긴 변 160px), 결과 화면 데이터. 최근 30개까지 두고 넘으면 오래된 것부터 지운다 [Q8].
- **FR9.2** 기록 화면은 흰 시트로 올라오며, 제목 "지난 분석"과 개수, 종류 칩(전체·사진·그림·스케치), 날짜 묶음(오늘·어제·M월 D일)을 보여 준다. 행에는 썸네일, 화가 이름, "종류 · 시각", %, 신뢰 등급 칩이 있다.
- **FR9.3** 행을 좌우로 110px 넘게 밀어 놓으면 그 기록이 지워지며 행이 밀려 나가고, 아래에 "기록을 지웠어요 · 되돌리기"가 4초 동안 보인다. 되돌리기를 누르면 원래 자리로 돌아온다. 덜 밀면 제자리로 돌아온다. 마우스로도 같은 동작을 한다.
- **FR9.4** 각 행에는 화면에 보이지 않는 "○○ 기록 지우기" 버튼을 두어 키보드·화면 읽기 사용자도 지울 수 있다.
- **FR9.5** "모두 지우기"를 누르면 "기록을 모두 지울까요?" 확인 창(취소·지우기)을 띄우고, 지우기를 눌렀을 때만 모두 지운다.
- **FR9.6** 행을 누르면 저장된 결과 화면 데이터로 결과 페이지를 연다(분석을 다시 하지 않음). 진행 막대·명화·색·선·화풍도 저장된 값으로 동작한다.
- **FR9.7** 기록이 없으면 "아직 기록이 없어요", "분석한 결과가 여기에 쌓여요."와 "사진 찍으러 가기" 버튼(첫 화면)만 보인다 [Q9].
- **FR9.8** 목록 아래에 "기록은 이 브라우저에만 저장돼요."를 보인다.
- **FR9.9** 기록 화면에서 왼쪽 위 아이콘을 누르거나 시트를 끌어내리면 FR6.4와 같은 내려가는 전환으로 첫 화면으로 돌아간다.

## 비기능 요구사항

- **NFR1 계약 유지**: `contracts/interfaces.md`, `render_card()`의 `(str, Figure)`, `app.analyze()`의 11개 키, `app.run()`의 `(text, fig, detail)`이 그대로이고, `tests/test_smoke.py`를 고치지 않은 채 `pytest` 전체가 통과한다.
- **NFR2 휴대폰 기준**: 360×780 화면에서 가로 스크롤이 생기지 않고 모든 페이지 내용이 시트 안에 들어간다. 누르는 영역은 44px 이상, 본문 글자 대비는 4.5:1 이상이다.
- **NFR3 움직임 줄이기**: 기기에서 "애니메이션 줄이기"를 켜면 FR1.8·FR3.2·FR4.3·FR5.1·FR6.1·FR6.2의 움직임 없이 최종 상태를 바로 보여 준다.
- **NFR4 추가 계산 제한**: CLIP 모델 호출(`embed_image`·`embed_text`) 수는 늘지 않는다. 명화 비교를 위해 늘어나는 계산은 `similar_works()` 1회(k=30)와 명화 이미지 최대 3장의 `extract_features()`뿐이다. `app.analyze()`·`app.run()`의 결과는 그대로다. 화면용 데이터 함수는 `result`와 `app.py`가 넘기는 명화 목록만 읽는다.
- **NFR5 품질 검사**: `ruff format .`·`ruff check .`·`pytest`가 통과한다. 새 함수에는 동작 테스트(정상 1개 이상, 낮음 등급·스케치 같은 경계 2개 이상)를 같은 PR에 넣는다.
- **NFR6 기록의 개인정보**: 기록과 썸네일은 브라우저 저장소에만 두고 서버로 보내지 않는다. 원본 사진은 저장하지 않는다.
- **NFR7 파일 제공 범위**: 브라우저로 보내는 명화 파일은 저장소 `data/` 폴더 안의 실제 이미지 파일(jpg·jpeg·png·webp)로만 한정한다. 링크와 `..`를 풀어 실제 위치로 확인하고, 그 밖의 경로는 보내지 않는다.

## 제약

- 자기 Unit 밖 `modules/` 파일은 고치지 않는다(`data.py`·`classify.py`·`features.py` 수정 금지).
- 새 패키지를 설치하지 않는다(`requirements.txt` 고정, Gradio 6.32.0).
- PR 3개로 나눈다: ① `explain.py` 화면용 데이터 함수 + 테스트, ② `static/g.css`·`static/g.js`, ③ `app.py` 연결 [Q1]. 이어서 ④ 명화 비교, ⑤ 기록 PR을 차례로 올린다 [Q10]. PR마다 파일 1~3개·300줄 이내를 목표로 하고, 넘으면 본문에 이유를 적는다.
- 두 기능을 #37에 넣은 것은 팀 규칙("이슈 하나 = PR 하나")과 다른 사람의 결정이므로 PR ④⑤ 본문에 그 이유를 적는다.
- 명화 이미지에는 화이트밸런스를 하지 않는다(`features.preprocess_input()`을 쓰지 않음).
- 브랜치 `feat/37-ui-design`, 머지 커밋만, `main` 직접 push 금지.
