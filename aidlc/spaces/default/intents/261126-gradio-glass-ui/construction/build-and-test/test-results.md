## 브라우저 확인

- **실행한 곳:** 실제 브라우저 엔진(헤드리스 Microsoft Edge). 실행한 것은 첫 화면이 그려지는 것뿐이다.
- **코드 생성 단계:** 520×780에서 찍었고, 로고·안내 띠·틀·도크·안내문이 그려지고 Gradio 기본 여백·푸터가 숨겨졌다.
- **이 단계:** 360×780으로 다시 찍었다. 헤드리스 창은 최소 폭이 약 500px이라 화면이 그 폭으로 그려진 뒤 360px만 잘려 찍혔다. 그래서 360px 화면의 가로 스크롤 여부는 이 사진으로 판단할 수 없다.
- **실행하지 않은 것:** 앨범 선택부터 화풍까지의 흐름, 시트 끌어내리기, 멈추기, 카메라 권한, 낮음 등급·스케치 화면, 애니메이션 줄이기.
  - 이 PC에는 브라우저 자동 조작 도구(Playwright 등)가 없다. 계획에도 없어 설치하지 않았다.
  - 그래서 사람이 브라우저 개발자 도구의 360×780 기기 모드로 확인해야 한다.
- **임시 파일:** 사진과 임시 브라우저 프로필은 확인 뒤 지웠다.

## 360×780 흐름 확인 (2026-11-27, 사람 요청으로 추가 실행)

- **방법:** 프로젝트 밖 임시 가상환경에 Playwright를 설치하고 설치된 Edge(헤드리스)로 360×780(모바일·터치, 배율 2)을 조작했다. 앱은 `tests/fakes.py` 가짜 모델로 띄웠고, 높음·낮음 화면은 신뢰 등급을 강제한 서버로 각각 확인했다. 프로젝트 의존성은 바꾸지 않았다.
- **통과한 시나리오 6개:** 콘솔 오류 없음, 모든 화면에서 `scrollWidth = clientWidth = 360`(가로 스크롤 없음).
  - 기본(높음): 앨범 → 분석 중 → 결과 자동 이동 → 색·선 → 화풍, 진행 막대 이동, 짧은 끌기(60px) 제자리, 긴 끌기(220px) 첫 화면, 분석 중 로고로 멈춤 후 늦은 결과 무시, "다른 이미지로 해 보기" 뒤 재분석
  - 낮음 등급, 스케치(선 5축 레이더), 애니메이션 줄이기(전환 직후 최종 상태)
  - 카메라 허용(가짜 카메라 미리보기 → 셔터 → 결과), 카메라 거부(셔터·앨범이 파일 선택 창을 열고 결과까지 감)
- **찾아서 고친 문제 4개** (모두 Gradio 전역 스타일이 `g.css`보다 우선하던 것과 줄바꿈):

  2. 낮음 안내 상자 안쪽 여백 없음: `.g-app p { padding: 0 }` → `.g-app .g-tip`
  3. 결과 화가 이름·화면 제목이 14px로 작게 나옴: `.gradio-container h1 { font-size: inherit }` → `.g-app .g-headline`, `.g-app .g-title`, `.g-app .g-num small`
  4. 한국어가 단어 중간에서 줄바뀜("특/징"), 스케치 레이더 "윤곽선 길이"가 왼쪽에서 잘림: `.g-app`에 `word-break: keep-all`, 레이더 viewBox를 축 이름 폭만큼 넓힘(`g.js` `labelWidth`)
