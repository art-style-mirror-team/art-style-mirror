## 주요 결정

- **화면 구조:** `gr.HTML` 하나가 화면 전체를 그려요. 분석 진행과 결과는 숨긴 `gr.JSON`(`visible="hidden"`)의 `change` 이벤트 `js`로 화면에 넘겨요. `visible=False`인 컴포넌트는 브라우저에 아예 만들어지지 않아서 `"hidden"`을 썼어요.
- **계획과 다른 점, CSS 위치:** `g.css`를 `css_template`이 아니라 `head`의 `<style>`에 넣었어요. `css_template`은 컴포넌트 선택자 안에 중첩돼서 `@keyframes`를 쓸 수 없기 때문이에요. 선택자는 모두 `.g-` 접두라 Gradio 스타일과 겹치지 않아요.
- **이벤트:** `trigger('submit', {path})`로 분석하고, `screen.stop(fn=None, cancels=[analysis])`로 멈춰요.
- **업로드 경로 검사:** 경로는 Gradio 업로드 폴더(`gradio.utils.get_upload_folder()`) 안의 실제 파일만 받아요. 경로를 풀어서 링크·`..`를 처리하고, 폴더 안인지와 파일인지를 확인해요.
- **사진 읽기:** PIL로 읽고 휴대폰 사진 회전을 바로잡은 뒤(`exif_transpose`) RGB uint8로 바꿔요.
- **모델 호출:** `analyze()`는 `_analyze_steps()`를 끝까지 돌려 같은 결과를 만들어요. 모델 호출 수와 순서는 그대로예요(NFR4).
- **대표 화풍:** 1위 화가의 비슷한 명화 style을 쓰고, 없으면 `styles_top3[0]`을 써요. explain은 다른 모듈을 import하지 않아요.
- **화면 문구:** 분석 단계 설명을 지금 전처리에 맞게 "긴 변을 512px로 맞춰요"로 바꿨어요. 시안의 "색 보정"은 #16 전에는 사실이 아니어서예요.

### 주요 결정

- **비교 명화:** `classify.similar_works(emb, k=30)`를 한 번만 부른다. 임베딩은 분석에서 받은 것을 다시 써서 CLIP 호출이 늘지 않는다(테스트로 `embed_image` 1회 확인). 높음·보통이고 1위 화가 작품이 있으면 그 작품을 맨 앞에 둔다.
- **명화 파일(NFR7):** 저장소 루트 기준으로 풀어 `data/` 안의 jpg·jpeg·png·webp만 읽는다. 긴 변 512px로 맞추고 화이트밸런스는 하지 않는다(테스트에서 `preprocess_input`이 불리면 실패). 브라우저에는 긴 변 320px JPEG data URL만 보내고 파일 경로는 보내지 않는다.
- **명화 레이더:** 색·선 페이지와 같은 축만 쓰고, 내 값과 차이가 작은 축 2개·큰 축 2개를 고른다(동점은 축 이름 순).
- **기록:** `localStorage` 키 `g-history-v1`, 최신 30개. 썸네일 160px, 명화 이미지는 96px로 줄여 저장하고 원본 사진은 저장하지 않는다. 깨진 항목은 경고 후 버린다. 기록 2개의 저장 크기는 약 34,000자(명화 이미지 있음)·18,000자(없음)였다.
- **색·선 움직임 순서:** 탭이 생기면 자식 순서가 바뀌어 `nth-child` 지연 대신 `g-after1~4` 클래스를 쓴다. 이미 본 탭은 `g-now`로 바로 보인다.

### 계획·요구사항과 다른 점

- **FR3.7 버튼 문구:** 맨 앞 명화가 1위 화가 작품일 때만 "가장 닮은 명화 보기", 아니면 "비슷한 명화 보기"다. 보통 등급이라도 1위 화가 작품이 없으면 명화 페이지 제목이 "가장 비슷한 명화예요"가 되므로 맞췄다.
- **명화가 1점뿐이면** "다른 명화와 비교" 칸을 숨긴다.
- **누르는 영역:** 레이더 탭(44px)과 기록 종류 칩(44px)을 시안(36px)보다 키웠다(NFR2).
- **저장 공간 부족:** 오래된 기록을 몰래 지우지 않고 "저장 공간이 부족해 기록을 저장하지 못했어요."만 알린다.
