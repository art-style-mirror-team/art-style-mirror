# Requirements — #9 kNN 투표 방식 판정

## Intent analysis

CLIP 임베딩의 이웃(kNN) 가중 투표로 화가·화풍을 판정하는 방식을 `modules/classify.py`에
비공개 함수로 추가한다. 목표는 두 가지다.

1. 여러 장의 CLIP 임베딩에 대해, 학습셋 이웃의 코사인 유사도를 이름별로 더한 **가중 투표
   로짓**을 결정적으로 계산한다(`_knn_logits`).
2. 그 로짓으로 **Top-k 정확도**를 계산하는 재사용 유틸을 만들어(`_topk_accuracy`) #10·#11과
   노트북 평가에서 공통으로 쓴다.

이는 판정 방식 비교(#9~#12) 실험의 한 축이며, 공개 계약(`contracts/interfaces.md`)과
`predict_clip()`은 바꾸지 않는다(#12 결정). 두 함수는 비공개이므로 계약 밖이다.

## Functional requirements

### FR1. kNN 가중 투표 로짓 — `_knn_logits(E, k, by, eps=1e-3)`
- **FR1.1** 입력 `E`는 `(n, 512)` 임베딩 여러 장을 받는다. `by`는 `"artist"` 또는 `"style"`.
- **FR1.2** 이웃은 **학습셋(`split == "train"`)에서만** 찾는다.
- **FR1.3** 질의와 색인 임베딩을 기존 `_l2_normalize`로 정규화한 **코사인 유사도**로 각 입력의
  상위 `k`개 이웃을 고른다.
- **FR1.4** 각 입력에 대해 이웃의 유사도를 `max(유사도, 0)`으로 **clip한 뒤**(음수 유사도는
  0으로 본다) `by` 기준 이름(화가 또는 화풍)별로 더한 **가중 투표**를 구한다.
- **FR1.5** 반환은 `(이름 목록, z)`이며 `z`는 `(n, 이름 수)` 행렬이고 `z = log(투표 + eps)`로
  둔다. `eps`는 키워드 인자로 노출하며 기본값 `1e-3`이다. FR1.4의 clip으로 투표 합은 항상 0
  이상이므로, 투표가 0인 이름은 `log(eps)`라는 유한한 값을 갖고 **모든 `z` 원소는 항상 유한하다**
  (NaN·-inf 없음). 한 입력의 모든 이웃 유사도가 음수여도 그 입력의 모든 z는 `log(eps)`다.
- **FR1.6** 반환 `z`의 이름 순위 동점은 **이름순**으로 끊어 결과가 결정적이다.
- **FR1.7** 화가·화풍 **이름 목록은 색인에서 읽어** 정한다(개수를 숫자로 고정하지 않는다). 색인
  메타는 위치 기준(`.iloc`)으로만 읽는다(라벨 인덱스 가정 금지).
- **FR1.8** 이웃을 고를 때 **유사도 동점**은 **색인 행 위치가 앞선 이웃을 먼저** 고른다(안정
  정렬). 이로써 중복·동일 임베딩이 있어도 선택이 결정적이다.
- **FR1.9** 비정상 입력 처리는 다음 **순서**로 한다: 먼저 `k <= 0`이거나 **학습셋이 비어 있으면
  `ValueError`** 를 낸다(학습셋이 비면 `n`과 무관하게 `ValueError`이며, 학습셋·`k` 검사를 `n`
  처리보다 **먼저** 한다). 그다음 `k`가 학습셋 크기보다 크면 학습셋 크기로 제한한다. 마지막으로
  입력이 0장(`n == 0`)이면 `(이름 목록, (0, 이름 수) 모양의 빈 z)`를 반환한다.

### FR2. Top-k 정확도 유틸 — `_topk_accuracy(z, names, labels, ks=(1, 3))`
- **FR2.1** 입력: `z`는 `(n, 이름 수)` 로짓 행렬, `names`는 열에 대응하는 이름 목록, `labels`는
  각 행의 **정답 이름 리스트(길이 n, 문자열)**.
- **FR2.2** 반환은 `dict {k: 정확도}` (예: `{1: 0.52, 3: 0.78}`). 각 입력에 대해 `z`가 큰 상위
  `k`개 이름 안에 정답 이름이 있으면 맞힌 것으로 센다. 상위 선택의 동점은 FR1.6과 같은 이름순
  규칙을 따른다.
- **FR2.3** `_knn_logits`의 반환 형식에만 의존하고 특정 `by`·이름 집합에 묶이지 않아 **#10·#11에서
  그대로 재사용**할 수 있다.
- **FR2.4** 경계 처리: `labels`의 정답 이름이 `names`에 없으면 그 입력은 **오답**으로 센다(오류를
  내지 않는다). `ks`의 원소가 이름 수보다 크면 **이름 수로 제한**해 계산한다.
- **FR2.5** 비정상 입력: `z`의 행 수와 `labels` 길이가 다르거나 `ks`에 0 이하 값이 있으면
  `ValueError`를 낸다.

### FR3. 동작 테스트 — `tests/test_classify.py`
- **FR3.1** 파일 끝에 `# --- #9 kNN` 절로 테스트를 추가한다.
- **FR3.2** 작은 **가짜 색인**을 `classify.load_index`에 monkeypatch해서 `_knn_logits`·
  `_topk_accuracy`의 동작(학습셋 한정 이웃, 투표 합산, 결정적 동점, 반환 형식, Top-k 계산)을
  검증한다.
- **FR3.3** `tests/test_smoke.py`는 수정하지 않는다.
- **FR3.4** 테스트는 다음 경계·설계 조건도 포함한다: 음수 유사도가 0으로 clip되어 모든 `z`가
  유한함(투표 0인 이름의 `z == log(eps)`), 기본 `eps == 1e-3`, 이웃·순위 동점의 결정성(FR1.6,
  FR1.8), `k <= 0`·빈 학습셋의 `ValueError`(학습셋이 비면 `n`과 무관, FR1.9), `labels`의 미지
  이름이 오답 처리됨(FR2.4), `z` 행 수와 `labels` 길이 불일치·`ks<=0`의 `ValueError`(FR2.5).

### FR4. 검증셋 평가 — `notebooks/eval.ipynb`
- **FR4.1** 맨 아래에 `#9 kNN` 절을 추가해 **검증셋(`split == "val"`)** 으로 `k = 5, 10, 20`의
  Top-1·Top-3 정확도를 계산한다. 평가는 **`by="artist"`와 `by="style"` 둘 다** 수행하되, k별
  비교 표의 기준은 **artist**로 한다(style은 참고로 함께 표시).
- **FR4.2** 첫 셀에서 `load_index()["meta"].attrs.get("fake")`를 출력하고, `True`면
  `가짜 색인 — 수치 기록 금지`라고 표시한다.
- **FR4.3** 화가 수는 숫자로 쓰지 않고 `meta["artist"].nunique()`로 계산해 보여 준다.
- **FR4.4** k가 작으면 표를 받은 이름이 3개 미만이라 Top-3가 이름순 동점에 좌우될 수 있으므로,
  k별 **"표를 받은 이름 수의 평균"** 도 함께 계산해 표시한다(artist·style 각각).
- **FR4.5** 셀 **출력은 지운 채로** 둔다. **테스트셋은 쓰지 않는다**.
- **FR4.6** `#9 kNN` 절의 셀은 **가짜 색인에서 오류 없이 실행**된다(수치는 기록하지 않고 출력은
  지운다).

## Non-functional requirements

- **NFR1 (결정성)** 같은 입력·색인이면 `_knn_logits`·`_topk_accuracy`의 결과가 항상 같다. 이웃
  선택 동점은 색인 위치순(FR1.8), 이름 순위 동점은 이름순(FR1.6)으로 끊는다.
- **NFR2 (데이터 분할)** 이웃 탐색은 학습셋만, 평가는 검증셋만 쓴다. 테스트셋은 열지 않는다(#26
  최종 평가 전용).
- **NFR3 (계약·범위 불변)** `contracts/interfaces.md`, `predict_clip()`, `tests/test_smoke.py`는
  바꾸지 않는다. 신규 함수는 비공개(`_` 접두)로 공개 계약 밖이다. 수정 파일은
  `modules/classify.py`, `tests/test_classify.py`, `notebooks/eval.ipynb`뿐이다.
- **NFR4 (품질 게이트)** 변경 후 `pytest` 전체 통과, `ruff format`·`ruff check` 통과.
- **NFR5 (평가 안정성 — 검증 기준)** `eps` 기본값은 `1e-3`이고, 투표가 0인 이름의 `z`는
  `log(1e-3)`와 같다(FR3.2·FR3.4 테스트로 확인). 이 값은 투표 0인 정답의 `log` 확률이 지나치게
  낮아져 #14 온도 보정의 NLL이 소수 사례에 끌려가는 것을 막기 위한 것이며, 더 작은 값(1e-9·
  1e-12)을 쓰지 않는다. 합격 기준: `pytest`·`ruff` 통과(NFR4)와 노트북 `#9 kNN` 셀이 가짜 색인
  에서 오류 없이 실행됨(FR4.6).

## Constraints

- **C1** 같은 CLIP 모델 버전으로 만든 색인을 쓴다(명화·사용자 입력 동일 버전).
- **C2** 최종 순위는 `fuse()` 결과만 쓴다. 이 작업은 로짓·정확도만 다루고 순위를 따로 뒤집지 않는다.
- **C3** 온도 `T`·가중치 `w`·등급 경계값은 검증셋으로만 정하며, 테스트셋으로 정하지 않는다.

## Assumptions

- **A1** `labels`의 이름은 색인의 화가/화풍 이름과 같은 표기를 쓰는 것이 정상이며, 다를 경우
  FR2.4에 따라 오답으로 센다(비교는 문자열 동등).
- **A2** `by`는 `"artist"`·`"style"` 두 값만 받는다. 색인 메타에 해당 열과 `split` 열이 있다.
- **A3** `k`가 학습셋 크기보다 크면 FR1.9에 따라 학습셋 크기로 제한한다(오류 아님).

## Out of scope

- UI(`app.py`)·색인 구축·프로필 변경.
