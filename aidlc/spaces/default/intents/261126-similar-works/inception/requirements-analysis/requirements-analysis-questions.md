# Requirements Analysis — 명료화 질문

> 스테이지: requirements-analysis · 범위: express · 깊이: Minimal
> 이슈 #13 — `modules/classify.py`의 `similar_works()` 실제 색인 검색 정리

## 공백 분석 결과

초기 요청이 여섯 개 차원(기능/비기능/사용자 시나리오/비즈니스/기술/품질) 모두에서
예외적으로 명확하고 완전하다고 판단했다. 따라서 Minimal 깊이 기준에 따라
담당자에게 물을 **열린 명료화 질문은 없다**. 요청이 직접 답하지 않은 구현 세부는
아래 가정(AS)으로 명시해 requirements.md에 기록한다.

- 반환 형식·함수 시그니처는 `contracts/interfaces.md`(변경 불가)가 정한다:
  `similar_works(emb, k=3) -> list[dict]`, 각 원소 `{"id", "artist", "style", "path", "score"}`,
  길이 ≤ k, score 내림차순, 유사도 0.95 이상 제외. (요청 + 계약에서 확정)
- L2 정규화 대상·코사인 유사도·0.95 제외·검색 범위(train/val/test 전체)·네이티브 타입·
  엣지 케이스(k=0, k>후보 수, 동점)는 요청이 직접 명시. (확정)

## 가정 (요청이 직접 답하지 않아 추론한 사항)

- **AS-1 (동점 결정성)**: 코사인 유사도가 같은 후보들 사이의 순서는 색인 행 순서
  (낮은 인덱스 우선)로 결정적으로 정한다. 즉 score 내림차순 1차 정렬 + 색인 위치
  오름차순 2차 정렬(안정 정렬). 요청의 "동점일 때도 결정적으로"를 이렇게 해석한다.
- **AS-2 (방어적 정규화)**: 색인·입력 임베딩이 이미 정규화되어 있더라도, 요청대로
  `similar_works()` 안에서 명시적으로 L2 정규화를 다시 수행한다(영벡터는 0으로 안전 처리).
- **AS-3 (네이티브 타입)**: `id`·`artist`·`style`·`path`는 `str`, `score`는 `float`로
  변환해 돌려준다(pandas/numpy 스칼라 타입을 반환하지 않는다).

위 가정이 담당자(홍예원)의 의도와 다르면 승인 게이트에서 변경을 요청하면 된다.
