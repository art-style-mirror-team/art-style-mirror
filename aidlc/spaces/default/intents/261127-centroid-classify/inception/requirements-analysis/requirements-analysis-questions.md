# Requirements Analysis — 명확화 질문 (#10 중심점 방식 판정)

> 깊이: Minimal (express). 요청은 모듈 담당자(B, `modules/classify.py`)가 직접 작성한
> 상세 사양이며, 함수 시그니처·입출력·예외·테스트 요구가 모두 지정되어 있다.

## 여섯 차원 완결성 점검

- **기능(Functional)**: `_centroid_logits(E, by, scale=LOGIT_SCALE)` 시그니처, 정규화·식·
  반환 모양·이름 목록 출처가 모두 지정됨. ✔ 완결
- **비기능(Non-functional)**: 계약 불변, `predict_clip()` 불변, pytest 전체 통과, Ruff 통과가
  기존 프로젝트 규칙으로 고정됨. 성능·보안 이슈 없음. ✔ 완결
- **사용자 시나리오/엣지**: 1차원 입력, 0장 입력, `scale <= 0`이 명시됨. ✔ 완결
- **비즈니스 맥락**: 분류 파이프라인의 내부 보조 함수(#8~#15 중 #10). 목표 명확. ✔ 완결
- **기술 맥락**: `_centroids()`·`_l2_normalize` 재사용, #9 `_knn_logits`와 같은 반환 모양.
  ✔ 완결
- **품질 속성**: 테스트 위치·monkeypatch 대상·`cache_clear()`·검사 항목이 지정됨. ✔ 완결

## 결론

여섯 차원 모두 사양에 의해 해소되어 **차단성 명확화 질문 없음**. 아래 요구사항으로 바로 진행한다.
남은 불확실성은 `requirements.md`의 `## 가정`·`## 미해결 질문`에 비차단 항목으로 기록한다.
