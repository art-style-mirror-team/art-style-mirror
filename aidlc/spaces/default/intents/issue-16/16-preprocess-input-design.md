# Issue #16 — `preprocess_input()` 설계

## 목표와 범위

`modules/features.py`의 `preprocess_input(img)`는 사용자 입력에 한해 종이 영역을 보수적으로 자르고, 입력과 종이 검출 여부에 독립적으로 화이트밸런스를 판단한 뒤 긴 변을 512px로 맞춘다. 함수 시그니처와 반환 형식은 유지하고 `contracts/interfaces.md`는 변경하지 않는다. 명화 경로에는 이 전처리를 적용하지 않는다.

## 처리 흐름

1. 입력 정규화와 형식 검증을 유지한다(2D 그레이스케일 및 RGBA 입력 처리 포함).
2. RGB에서 밝고 채도가 낮은 종이 후보를 만들고, 형태학적 닫힘과 외곽 윤곽선으로 종이 영역을 찾는다. 크고 종이 경계로 판단할 수 있는 윤곽선이 있을 때만 해당 바운딩 박스를 자른다. 신뢰할 만한 종이 경계가 없으면 자르지 않는다.
3. 현재 이미지의 HSV에서 밝기 상위 40%(V가 60백분위 이상)이면서 채도가 115 이하인 픽셀을 화이트밸런스 후보로 삼는다. 후보 비율이 20% 이상일 때만 그 픽셀의 RGB 채널별 중앙값으로 보정한다. 보정 배율은 0.75~1.8로 제한하고 결과를 uint8 범위로 자른다. 후보 비율이 20% 미만이거나 채널 중앙값을 사용할 수 없으면 보정을 건너뛴다.
4. 자르기와 보정 후 종횡비를 유지해 긴 변을 512px로 리사이즈한다. 축소는 `INTER_AREA`, 확대는 `INTER_CUBIC`을 사용한다.

## 알려진 한계

- 어두운 바탕 가운데 큰 흰 사각형이 있는 디지털 그림은 흰 부분만 종이로 검출되어 그 부분만 남도록 잘릴 수 있다.
- 화면 대부분이 밝은 무채색이나 연한 노란색인 그림은 후보 비율 조건을 충족해 화이트밸런스 보정 대상이 될 수 있다.

## 계약과 검증

- 반환은 RGB `np.ndarray`, `uint8`, shape `(H, W, 3)`이며 긴 변은 512px이다. 원본 배열은 직접 수정하지 않는다.
- 종이 영역 자르기, 화면을 채운 따뜻한 조명 스케치의 중립화, 종이 검출 없이도 화이트밸런스를 판단하는 동작, 단색의 채도 높은 컬러 입력 보존을 `tests/test_features.py`에서 확인한다.
- 로컬 Windows 보안 정책으로 cv2/numpy 실행이 차단되어 pytest는 GitHub CI에서 검증한다.
