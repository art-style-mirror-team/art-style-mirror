# Issue #16 — `preprocess_input()` 설계

## 목표와 범위

`modules/features.py`의 `preprocess_input(img)`는 사용자 입력에 한해 종이 영역을 보수적으로 자르고, 입력과 종이 검출 여부에 독립적으로 화이트밸런스를 판단한 뒤 긴 변을 512px로 맞춘다. 함수 시그니처와 반환 형식은 유지하고 `contracts/interfaces.md`는 변경하지 않는다. 명화 경로에는 이 전처리를 적용하지 않는다.

## 처리 흐름

1. 입력 정규화와 형식 검증을 유지한다(2D 그레이스케일 및 RGBA 입력 처리 포함).
2. RGB에서 밝고 채도가 낮은 종이 후보(V가 120 이상, 채도 90 이하)를 만들고, 형태학적 닫힘과 외곽 윤곽선으로 종이 영역을 찾는다. 크고 볼록한 종이 경계가 확인되면 윤곽 다각형의 바운딩 박스를 사용해 배경이 섞인 외곽을 제외하고 각 변을 1% 안쪽으로 트리밍한다. 신뢰할 만한 종이 경계가 없으면 자르지 않는다.
3. 자른 이미지의 긴 변이 최대 512px인 작업 사본에 가우시안 블러를 적용한다. 밝기 상위 절반의 채널별 중앙값을 조명 색으로 보고, 최소 채널이 40 미만이거나 보정 배율 최댓값이 1.8 초과이면 보정을 건너뛴다.
4. 조명 색을 제거한 뒤 밝기 50 초과 픽셀 중 채널 차이가 20 초과인 비율이 2%를 넘으면 컬러 그림으로 보고 원본 색을 보존한다. 이 비율이 2% 이하이고 Canny 에지 비율이 0.2% 이상이면 채널별 조명 보정을 적용한 뒤 흑백 3채널 이미지로 변환한다. 에지가 부족한 단색 면도 보정하지 않는다.
5. 자르기와 판정 후 종횡비를 유지해 긴 변을 512px로 리사이즈한다. 축소는 `INTER_AREA`, 확대는 `INTER_CUBIC`을 사용한다.

## 알려진 한계

- 어두운 바탕 가운데 큰 흰 사각형이 있는 디지털 그림은 흰 부분만 종이로 검출되어 그 부분만 남도록 잘릴 수 있다.
- 거의 한 색인 연한 그림(예: 푸른 회색 안개 풍경과 나무)은 픽셀만으로 노란 조명 아래 스케치와 구별할 수 없다. #25 통합에서 B의 `detect_type()` (CLIP) 결과와 맞춰 처리한다.

## 계약과 검증

- 반환은 RGB `np.ndarray`, `uint8`, shape `(H, W, 3)`이며 긴 변은 512px이다. 원본 배열은 직접 수정하지 않는다.
- 종이 영역 자르기, 화면을 채운 따뜻한 조명 스케치의 중립화, 종이 검출 없이도 화이트밸런스를 판단하는 동작, 단색의 채도 높은 컬러 입력 보존을 `tests/test_features.py`에서 확인한다.
- 로컬 Windows 보안 정책으로 cv2/numpy 실행이 차단되어 pytest는 GitHub CI에서 검증한다.
